# 号池额度与用量监控

运维监控启用时，服务会在后台按账号收集已有的上游用量窗口、余额或积分，包含停用、暂停调度或处于异常状态的账号，并在管理端「运维监控」的账号并发/可用性卡片中展示采样时间、来源、窗口和余额。平台或分组汇总显示可判断、接近耗尽、未知和没有可用查询来源的账号数。账户详情中的余额和供应商数据只提供给管理员。

## 数据来源与限制

| 账号 | 数据来源 |
| --- | --- |
| OpenAI OAuth | 只读查询 ChatGPT/Codex 用量接口；Spark 影子账号使用其独立窗口。普通 OpenAI API Key 不会被当作有现金余额接口。 |
| Anthropic OAuth / Setup Token | OAuth 查询用量接口；Setup Token 使用请求响应中已有的被动采样。 |
| Gemini | 依据已配置的套餐档位和本地请求记录估算窗口用量，界面明确标为本地估算。 |
| Antigravity | 上游按模型用量窗口及返回的 AI 积分。 |
| Grok | 既有计费快照和响应头中的请求/令牌窗口；能取得时单独显示美元预付余额。 |
| Kimi、智谱、MiniMax、OpenCode Go 订阅 | 对已有支持的 Coding Plan / Go 查询接口读取各窗口。 |
| Kimi、DeepSeek 按量付费 | 对已有支持的余额接口读取余额，分别保留货币单位。Kimi 自动查询只使用官方 Moonshot 中国区账号，避免将第三方密钥发送到固定的官方余额端点。 |
| Ollama Cloud | 使用已经配置的 Ollama 设置页会话及其现有刷新机制，不绕过账号的刷新开关。 |

上游未提供、配置不适用、查询失败、部分数据缺失或采样超过两小时的数据标为未知；不支持查询的账号单独计数，不当作余额为零或额度充足。窗口重置后需要新采样，不能把旧窗口当成新窗口。不同套餐的百分比不代表相同 token 数，不同币种也不会相加或换算。已监控账号中，可识别为相同提供商凭据或相同 OpenAI 用户与工作区的账号行会在额度汇总中去重；Spark 影子行保留独立窗口。不支持查询的数量按账号行统计。缺少可靠身份信息时不会推测两个账号是否相同。

管理员为 API Key / Bedrock 账号设置的本地美元消费限额也会显示并参与用量告警，和上游余额分开标注。日、周窗口过期后按本地限额规则归零；若上游采样仍未知，账号可同时列入「上游未知」和「接近耗尽」。

后台任务每分钟启动一轮，每轮最多处理 40 个到期账号，最多四个并发；完整采样通常间隔 5 分钟，失败或部分采样后至少间隔 2 分钟。大号池或持续的上游超时可能延长实际间隔。使用跨实例锁避免并发探测同一账号；已配置的 Redis 锁不可用时暂不采样，避免不同实例重复探测。OpenAI 用量读取和其他提供商查询会产生额外的上游读取请求，并可能触发正常的凭据刷新；Ollama 仍遵循自身会话和刷新设置。采集过程不主动修改账号调度状态。

## 告警和邮件

安装迁移会建立以下可编辑的默认运维告警：

| 规则 | 默认条件 |
| --- | --- |
| 号池额度不足 | 至少一个可判断账号的非分钟窗口用量或本地消费限额达到 90%，或其国产按量余额低于现有停调阈值，或提供商积分达到其最低余额。持续 2 分钟。 |
| 号池余额缓冲不足 | 对每个账号分别计算 USD 余额÷5 和 CNY 余额÷30，取其中较大值；任一账号的这个值不高于 1 且持续 2 分钟时告警。 |
| 号池美元 / 人民币余额不足 | 按单一币种的最低值分别比较 5 USD / 30 CNY；默认关闭，可按需要启用。 |
| 号池额度采样异常 | 可监控账号的采样未知，持续 30 分钟。 |

余额缓冲规则不会换算或相加币种：同一账号只要有一个已知币种高于对应缓冲基数，就不会因另一币种为零而触发此规则。阈值可调整，例如将倍数设为 2 即使用 10 USD / 60 CNY 缓冲。单币种最低余额规则比较已观测账户的最低值，不计算跨供应商总余额。也可以建立按分组过滤的规则，或使用最高已知用量百分比指定其他阈值。分钟级 RPM 窗口会显示，但不作为补号用的长期额度。

请在运维告警设置中启用邮件告警、填写收件人，并配置可用的 SMTP。如果运维收件人为空，同时已启用账号额度通知，号池告警会复用该通知中已验证且未停用的收件人。没有可用收件人时仍可在运维界面看到告警事件，但不会收到邮件。事件和邮件会列出最多五个相关账号的名称与 ID，更多账号请在管理页查看。未知采样不能证明已恢复；部分可用采样仍可触发告警，缺失采样期间不会据此自动解除尚未证实恢复的告警。邮件发送失败或收件人后来配置完成时，仍在触发中的事件会限频重试。
